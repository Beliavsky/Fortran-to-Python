Type-bound-call follow-up (2026-10-04)
-------------------------------------
The original counter regression printed 3 in Fortran but 0 in Python: its
type-bound CALL was omitted. The parser confused a type's CONTAINS with the
module's CONTAINS, discarded binding declarations, and only accepted simple
procedure names in CALL statements.
The fix emits methods forwarding to translated procedures and recognizes
CLASS(type) dummies. The regression now covers renamed bindings, named PASS
in a non-first position, NOPASS, optional/keyword arguments, scalar OUT values,
no-argument CALL without parentheses, bound function expressions, nested
objects, bound-to-bound calls, and component-array indexing. It is no longer
an expected failure. Deferred/generic bindings and indexed-object CALLs are
rejected explicitly; general inheritance/polymorphic dispatch is not claimed.
The refreshed batch comparison passes:
  reports\xf2p_batch_20261004_132123_mcdzcb_e\results.txt

A separate pre-existing issue surfaced while constructing the larger case:
explicit array-component initializers such as integer :: samples(2) = [2,4]
were ignored by the dataclass emitter, which used np.empty instead. That issue
is now fixed, and the counter uses its declaration initializer again.

Array-component initialization follow-up (2026-10-04)
---------------------------------------------------
The factory now allocates fresh typed storage and fills it from the initializer.
CHARACTER initializers are padded/truncated to their declared length. Each
derived-type element is copied independently, including default-constructed
elements, rather than sharing a scalar-expanded object reference.
The execution regression covers parameter-based initialization, real fractions,
scalar matrix fill, RESHAPE-based matrix values, logical/complex scalar values,
character arrays, empty arrays, default-derived and explicitly initialized
derived arrays. Mutations verify independence between elements and instances.
Unit tests also check integer conversion and preservation of the initializer.
The fresh execution comparison passes:
  reports\xf2p_batch_20261004_134052_rg79j4pk\results.txt

Expression limitations discovered while expanding the regression (now fixed):
  [(1d0,2d0),(-3d0,4d0)] becomes a list of Python tuples, not complex numbers.
  a%copies(1)%values(1) leaves the final array access as a function call.
These were separate from the initializer factory and are now fixed. The
regression uses the original complex vector initializer and direct chained
component-array reads and writes instead of the earlier workarounds.

Component-expression follow-up (2026-10-04)
------------------------------------------
Each array-constructor element is translated recursively. Complex pairs become
complex values even in arithmetic expressions and nested/keyword arguments;
function argument lists and quoted strings retain their original meaning.
The reference scanner preserves the chain after subscripting a component or
derived object. Component declarations supply bounds and assignment conversion
metadata. Tests exercise vectors, matrices, non-default lower bounds, reverse
sections, scalar expansion, fractional-to-integer conversion, masked writes,
and arrays of derived objects whose own bounds differ from their components.
Indexed-object bound CALLs and general inheritance are still not supported.
Fresh execution comparison:
  reports\xf2p_batch_20261004_140115_gz11_r5u\results.txt
Full suite after both expression fixes: 113 passed, 7 strict expected failures.

ALLOCATE SOURCE/MOLD follow-up (2026-10-04)
-----------------------------------------
The user's xmold.f90 allocated y with SOURCE=x and z with MOLD=x. Only
ALLOCATE(a(n)) had been recognized, so the option forms fell into assignment
translation and emitted calls to a nonexistent Python allocate function.
The new parser separates objects from options. SOURCE values are copied;
MOLD values are never copied/read for intrinsic allocation. Derived-type
MOLD allocation applies declared component defaults, not the model's values.
Models are evaluated once, including allocations of multiple objects.
Explicit dimensions and whole-variable model bounds are captured in the
current unit; sections/expressions use one-based bounds. Tests check empty
extents, scalars, matrices, integer/logical/complex/character arrays, derived
element independence, allocatable components, and STAT/ERRMSG behavior.
Unsupported type-spec allocation, deferred-length CHARACTER, and non-default
allocated-component bounds receive explicit diagnostics. Bound propagation
through allocatable procedure dummies remains a separate limitation.
The regression uses numeric logical indicators to isolate allocation from
the pre-existing list-directed logical-output discrepancy (T versus True).
Fresh execution comparison:
  reports\xf2p_batch_20261004_142418_idr78dcs\results.txt
The user's xmold.f90 also passes --run-both.
Full suite: 123 passed, 7 strict expected failures in 150.02 seconds.

Location-intrinsic follow-up (2026-10-04)
---------------------------------------
MINLOC, MAXLOC, and FINDLOC now use runtime helpers instead of undefined
Python calls. Results are one-based positions, not declared array subscripts.
DIM removes the searched dimension; absent DIM returns a rank-one coordinate
vector in Fortran array-element order. MASK, BACK, integer KIND, empty arrays,
all-false masks, no matches, and blank-padded CHARACTER comparisons are tested.
The original xloc.f90 passes --run-both; the expanded comparison matches:
  reports\xf2p_batch_20261004_145628_1_52fg9u\results.txt
tests/cases/stash is excluded from automatic execution-test discovery.
Full suite: 128 passed, 7 strict expected failures in 188.79 seconds.
