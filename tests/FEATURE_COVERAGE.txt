Scope
-----

absent optional arguments forwarded to other procedures, polymorphism,
overridden bindings, and impure elemental array calls with well-defined results.

Type-bound-call follow-up (2026-10-04)
-------------------------------------
The original counter regression printed 3 in Fortran but 0 in Python: its
type-bound CALL was omitted. The parser confused a type's CONTAINS with the
module's CONTAINS, discarded binding declarations, and only accepted simple
procedure names in CALL statements.
The fix emits methods forwarding to translated procedures and recognizes
CLASS(type) dummies. The regression now covers renamed bindings, named PASS
in a non-first position, NOPASS, optional/keyword arguments, scalar OUT values,
no-argument CALL without parentheses, bound function expressions, nested
objects, bound-to-bound calls, and component-array indexing. It is no longer
an expected failure. Deferred/generic bindings and indexed-object CALLs are
rejected explicitly; general inheritance/polymorphic dispatch is not claimed.
The refreshed batch comparison passes:
  reports\xf2p_batch_20261004_132123_mcdzcb_e\results.txt

A separate pre-existing issue surfaced while constructing the larger case:
explicit array-component initializers such as integer :: samples(2) = [2,4]
were ignored by the dataclass emitter, which used np.empty instead. That issue
is now fixed, and the counter uses its declaration initializer again.

Array-component initialization follow-up (2026-10-04)
---------------------------------------------------
The factory now allocates fresh typed storage and fills it from the initializer.
CHARACTER initializers are padded/truncated to their declared length. Each
derived-type element is copied independently, including default-constructed
elements, rather than sharing a scalar-expanded object reference.
The execution regression covers parameter-based initialization, real fractions,
scalar matrix fill, RESHAPE-based matrix values, logical/complex scalar values,
character arrays, empty arrays, default-derived and explicitly initialized
derived arrays. Mutations verify independence between elements and instances.
Unit tests also check integer conversion and preservation of the initializer.
The fresh execution comparison passes:
  reports\xf2p_batch_20261004_134052_rg79j4pk\results.txt

Expression limitations discovered while expanding the regression (now fixed):
  [(1d0,2d0),(-3d0,4d0)] becomes a list of Python tuples, not complex numbers.
  a%copies(1)%values(1) leaves the final array access as a function call.
These were separate from the initializer factory and are now fixed. The
regression uses the original complex vector initializer and direct chained
component-array reads and writes instead of the earlier workarounds.

Component-expression follow-up (2026-10-04)
------------------------------------------
Each array-constructor element is translated recursively. Complex pairs become
complex values even in arithmetic expressions and nested/keyword arguments;
function argument lists and quoted strings retain their original meaning.
The reference scanner preserves the chain after subscripting a component or
derived object. Component declarations supply bounds and assignment conversion
metadata. Tests exercise vectors, matrices, non-default lower bounds, reverse
sections, scalar expansion, fractional-to-integer conversion, masked writes,
and arrays of derived objects whose own bounds differ from their components.
Indexed-object bound CALLs and general inheritance are still not supported.
Fresh execution comparison:
  reports\xf2p_batch_20261004_140115_gz11_r5u\results.txt
Full suite after both expression fixes: 113 passed, 7 strict expected failures.

ALLOCATE SOURCE/MOLD follow-up (2026-10-04)
-----------------------------------------
The user's xmold.f90 allocated y with SOURCE=x and z with MOLD=x. Only
ALLOCATE(a(n)) had been recognized, so the option forms fell into assignment
translation and emitted calls to a nonexistent Python allocate function.
The new parser separates objects from options. SOURCE values are copied;
MOLD values are never copied/read for intrinsic allocation. Derived-type
MOLD allocation applies declared component defaults, not the model's values.
Models are evaluated once, including allocations of multiple objects.
Explicit dimensions and whole-variable model bounds are captured in the
current unit; sections/expressions use one-based bounds. Tests check empty
extents, scalars, matrices, integer/logical/complex/character arrays, derived
element independence, allocatable components, and STAT/ERRMSG behavior.
Unsupported type-spec allocation, deferred-length CHARACTER, and non-default
allocated-component bounds receive explicit diagnostics. Bound propagation
through allocatable procedure dummies remains a separate limitation.
The regression uses numeric logical indicators to isolate allocation from
the pre-existing list-directed logical-output discrepancy (T versus True).
Fresh execution comparison:
  reports\xf2p_batch_20261004_142418_idr78dcs\results.txt
The user's xmold.f90 also passes --run-both.
Full suite: 123 passed, 7 strict expected failures in 150.02 seconds.

Location-intrinsic follow-up (2026-10-04)
---------------------------------------
MINLOC, MAXLOC, and FINDLOC now use runtime helpers instead of undefined
Python calls. Results are one-based positions, not declared array subscripts.
DIM removes the searched dimension; absent DIM returns a rank-one coordinate
vector in Fortran array-element order. MASK, BACK, integer KIND, empty arrays,
all-false masks, no matches, and blank-padded CHARACTER comparisons are tested.
The original xloc.f90 passes --run-both; the expanded comparison matches:
  reports\xf2p_batch_20261004_145628_1_52fg9u\results.txt
tests/cases/stash is excluded from automatic execution-test discovery.
Full suite: 128 passed, 7 strict expected failures in 188.79 seconds.

ATAN2D/ATAN2PI, and two-argument ATAND/ATANPI mappings. NORM2 now uses scaled

Host association and LOG10 follow-up (2026-10-04)
------------------------------------------------
Program-internal procedures are emitted inside main and bind host variables
with nonlocal. Module procedures bind module state with global. Locals and
dummy arguments shadow outer variables. Inherited array bounds, element types,
derived types, and CHARACTER lengths remain available for expression and
assignment translation. Tests cover repeated main invocations without leaked
counter state, local shadowing, module state, a parent's dummy argument,

Numerical output comparison follow-up (2026-10-04)
-------------------------------------------------
CLI and batch share a stdout comparator. Real tokens use relative tolerance
1e-9 and absolute tolerance 1e-11 by default; --rtol and --atol override them.
Integer tokens and nonnumeric text remain exact. Fortran D exponents, matching
NaNs, same-sign infinities, and signed zero are covered. Default comparison
ignores whitespace and line wrapping. Diagnostics identify the first genuine
mismatch, skipping earlier numerically close lines. A mismatch exits nonzero.

--diff-exact implies --run-diff and restores normalized-line text comparison,
not byte-for-byte comparison. Tests cover single-file, per-file, and grouped
CLI modes, batch integration, tolerance validation, large integer differences,
and missing output. The unchanged xintrinsics.f90 now reports Run diff: MATCH.
--time-both inherits comparison; use --run-both --time for timing intentionally
different output without comparing it.

Focused comparison/batch tests: 30 passed. Full suite: 166 passed, 6 strict
expected failures in 343.94 seconds.

BLOCK lexical-scope follow-up (2026-10-04)
-----------------------------------------
BLOCK declarations no longer overwrite enclosing symbol bindings. Locals use
collision-free generated names; nested/sibling shadowing preserves outer values.
Automatic storage is initialized on entry rather than hoisted, so loop-dependent
explicit array bounds are evaluated at the right time. Block parameters, strings,
components, keyword arguments, operator spelling, and exponent literals are
covered by focused tests. Program, subroutine, and module-function contexts pass.
SAVE/initialized nonparameter locals, local imports, and local derived-type
definitions are rejected explicitly pending support for their storage/scope rules.

The unchanged tests\cases\more\test25_block_scope.f90 now reports MATCH (the
outer x remains 10). Named-loop EXIT/CYCLE is still a separate open bug.
Additional probing exposed a separate issue with assignments to USE-associated
module variables in main creating Python-local bindings; not changed here.

Verification: 131 non-execution tests passed in 71.12 seconds; existing execution
corpus plus the new block_scope case: 46 passed, 6 expected failures in 325.85
seconds. The 60 exploratory cases in tests\cases\more were excluded from that
execution run because their known unsupported features are still under review.

Named DO EXIT/CYCLE follow-up (2026-10-04)
----------------------------------------
Named loop transfers resolve their target rather than always breaking/continuing
the innermost Python loop. Current-loop transfers stay native break/continue;
outer-loop transfers use a private exception caught by the target iteration.
Intervening loop termination assignments are skipped during unwinding. Only the
private control exception is caught; unrelated runtime errors still propagate.
Counted DO, DO WHILE, bare DO, nested targets, case-insensitive construct names,
descending steps, empty loops, BLOCK/SELECT CASE, and translator reuse are tested.
Unknown/mismatched names fail explicitly; named DO CONCURRENT remains unsupported.

The unchanged tests\cases\more\test46_named_loop_cycle_exit.f90 now reports
MATCH with total 63 (previous translation returned 84). The new named_loop_control
fixture also matches compiled Fortran, including DO-variable values after normal
termination, EXIT, and outer CYCLE transfers. Focused checks: 9 passed.
Established suite: 185 passed, 6 expected failures, 60 exploratory cases excluded,
in 294.28 seconds. No unexpected failures.

USE-associated module-state follow-up (2026-10-04)
-------------------------------------------------
Modules in one Fortran input source now expose variable metadata to USE scopes.
Main and module/internal procedures bind imported variables to the same Python
global storage, rather than creating main-local copies. Imported storage is not
reinitialized on main entry. Array element types/lower bounds and CHARACTER
lengths are retained. ONLY, PUBLIC/PRIVATE (including private-default reexports),
transitive USE, procedure-local USE, and local/BLOCK shadowing are tested.
The new use_module_state fixture matches Fortran for scalars, non-one-based
arrays, strings, module-internal helpers, and program-internal updates.

Remaining restrictions fail explicitly: renamed USE variables; duplicate mutable
variable names in different flattened modules; mutable variable imports in the
CLI's multi-file --mode-program path (which emits separate Python files). Combine
module and program into one Fortran source for shared-state translations until
separate module namespaces are implemented. Procedure-only imports are unaffected.

Established-suite run: 196 passed, 6 expected failures, 60 exploratory cases
excluded, in 401.97 seconds. A subsequent non-execution run including two additional
guard/accessibility regressions passed all 150 tests in 81.62 seconds. The unchanged
six expected failures remain; there were no unexpected failures. The standalone
use_module_state.f90 --run-diff also reports MATCH.
