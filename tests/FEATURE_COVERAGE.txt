Language-feature execution survey (2026-10-04)
=============================================

All 17 new reference programs compile and run with the local gfortran.
Initially ten translations matched and seven exposed translator defects.
No translator or runtime changes were made for the initial survey.
After the type-bound-call fix, eleven match and six remain failing.

Confirmed failures (strict xfail in test_xf2p_execution.py)
--------------------------------------------------------
impure_elemental: UnboundLocalError for module variable calls.
  The translated procedure updates module state without declaring it global.
  This scalar-only test avoids array elemental evaluation-order assumptions;
  it isolates module-state mutation rather than proving general impure
  elemental support or lack of support.

type_extension: AttributeError: 'child' object has no attribute 'base'.
  Explicit parent-component access value%base%id is not represented correctly.

selected_integer_kind: NameError for selected_int_kind.
selected_real_kind: NameError for selected_real_kind.
selected_logical_kind: NameError for selected_logical_kind.
  Missing helpers prevent initialization of kind parameters.
  Tests compare numeric values and positive-kind checks, not processor-specific
  kind numbers. The integer case also exercises a large kind-suffixed literal.

execute_command_line: NameError for execute_command_line.
  The test only runs 'echo command_ok' synchronously and checks exitstat/cmdstat.
  It does not launch arbitrary commands or perform destructive operations.

Scope
-----
Passing these small cases is not a complete language-support guarantee.
Additional tests should cover multiple concurrent indices, locality clauses,
absent optional arguments forwarded to other procedures, polymorphism,
overridden bindings, and impure elemental array calls with well-defined results.

Type-bound-call follow-up (2026-10-04)
-------------------------------------
The original counter regression printed 3 in Fortran but 0 in Python: its
type-bound CALL was omitted. The parser confused a type's CONTAINS with the
module's CONTAINS, discarded binding declarations, and only accepted simple
procedure names in CALL statements.
The fix emits methods forwarding to translated procedures and recognizes
CLASS(type) dummies. The regression now covers renamed bindings, named PASS
in a non-first position, NOPASS, optional/keyword arguments, scalar OUT values,
no-argument CALL without parentheses, bound function expressions, nested
objects, bound-to-bound calls, and component-array indexing. It is no longer
an expected failure. Deferred/generic bindings and indexed-object CALLs are
rejected explicitly; general inheritance/polymorphic dispatch is not claimed.
The refreshed batch comparison passes:
  reports\xf2p_batch_20261004_132123_mcdzcb_e\results.txt

A separate pre-existing issue surfaced while constructing the larger case:
explicit array-component initializers such as integer :: samples(2) = [2,4]
are ignored by the dataclass emitter, which uses np.empty instead. The bound
call regression initializes samples explicitly in executable code to isolate
the binding fix. Array-component initialization still needs its own regression
and fix; scalar-component initialization is exercised by the counter test.
